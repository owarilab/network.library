## Common Commands

- **Build the server binary**
  ```bash
  make
  ```
  Builds `qs_tool_server` and links the core library.

- **Clean build artifacts**
  ```bash
  make clean
  ```

- **Run the server**
  ```bash
  ./qs_tool_server
  ```
  The server serves the front‑end from `www/` at `http://localhost:4444/`.

- **Open the front‑end**
  Open `www/index.html` in a browser. The UI is a Canvas‑based dot editor.

## High‑Level Architecture

- **Core C library** (`core/src`) provides networking and HTTP handling. It is compiled into `libqs_core.a` and linked by the Makefile.

- **Server binary** (`qs_tool_server`) runs the C server and serves static files from `www/`.

- **Front‑end** (`www/`) is vanilla JavaScript. It implements a Scene/SceneManager pattern with modules such as `pixel_data.js`, `layer_data.js`, `scene_manager.js`, and UI components under `ui/`.

- **Project data flow**: `ProjectData`, `ProjectSession`, and `ProjectSerializer` manage project state and persistence (`.qsproj`).

- **Rendering**: `PixelCanvas` draws pixel data to an off‑screen canvas; `PixelCanvas.drawImage` handles image scaling.

- **Input handling**: `Input` centralises keyboard/mouse/touch events.

- **Scene hierarchy**: `TitleScene` → `ProjectTopScene` → `EditorScene`. Each scene implements `onEnter/onLeave` hooks.
