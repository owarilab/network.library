# レイヤー操作 実装計画書

最終更新: 2026-04-23

## 1. 目的

`sample/qs_tool_server` のレイヤー機能を、
「最低限レイヤーがある状態」から「実務で使える状態」まで引き上げる。

今回の対象は `FEATURE_ROADMAP.md` の次の5項目。

1. レイヤー名変更
2. 不透明度スライダー
3. レイヤーロック
4. レイヤー複製
5. レイヤー結合

この機能の主目的は次の通り。

1. 線画、影、当たり判定下書きなどを分けて安全に編集できるようにする
2. タイル単位レイヤー編集を量産作業でも破綻しない操作系にする
3. Undo / Redo、選択ツール、一括編集に接続しやすい土台を作る

---

## 2. 現状整理

現状ではレイヤー基盤はすでに存在する。

実装済み:

1. `LayerData`
   - `addLayer()` / `removeLayer()` / `moveLayer()`
   - `toggleVisibility()` / `setOpacity()`
   - `composite()` によるアルファ合成
2. `LayerPanel`
   - レイヤー一覧表示
   - 可視/不可視トグル
   - 追加、削除、上下移動
   - ダブルクリックによるレイヤー名インライン編集
3. `AppData.layerData`
   - free モードと tileset モードを透過的に切り替える

未完成または不足している点:

1. タイルセットモードで多数レイヤーを扱う時の誤操作防止が弱い
2. 高度な UI 改善はまだ余地がある

つまり、現在は「レイヤーが存在する」段階であり、
「制作速度を上げるための管理機能」はまだ揃っていない。

---

## 3. 基本方針

### 3.1 既存 `LayerData` を中核に拡張する

レイヤー管理の責務は `LayerData` に集中させる。
`LayerPanel` や `EditorScene` にロジックを分散させない。

原則:

1. レイヤー構造変更は `LayerData` メソッド経由で行う
2. UI は `LayerData` を呼ぶだけに留める
3. 将来の Undo / Redo 導入時にコマンド化しやすい粒度で API を作る

### 3.2 まずは「安全性」と「管理性」を優先する

今回のレイヤー機能は、見た目を増やすためではなく、
誤編集を減らし、整理しやすくするためのものと捉える。

そのため優先順位は次の通り。

1. ロック
2. 不透明度
3. 複製
4. 結合
5. UI の磨き込み

### 3.3 free モードと tileset モードの両方で同じ操作感にする

`AppData.layerData` の抽象化を活かし、
どちらのモードでもレイヤー操作 UI と API を共通化する。

## 4. 対象機能ごとの要件

### 4.1 レイヤー名変更

現状:

1. `LayerPanel` のダブルクリックでインライン編集できる
2. ただし計画・履歴・入力制約が未整理

今回の到達点:

1. 名前変更の正式サポート
2. 空文字や過度に長い名前の扱いを定義
3. Undo / Redo コマンド化しやすい更新経路に統一

仕様案:

1. 空文字は不可
2. 前後空白は trim する
3. 最大長は 32 文字程度に制限
4. 同名レイヤーは許可する
5. rename 専用 API を `LayerData` に追加する

候補 API:

```javascript
renameLayer(index, newName)
```

### 4.2 不透明度スライダー

現状:

1. `setOpacity(index, opacity)` は存在する
2. LayerPanel 下部詳細欄のスライダー UI を実装済み
3. drag 中 preview、mouse up 時 1 履歴化まで実装済み
4. ブラウザ上で opacity 変更と Undo / Redo 挙動を確認済み

今回の到達点:

1. アクティブレイヤーの不透明度を UI から変更可能にする
2. 数値表示で現在値を確認できるようにする
3. 連続ドラッグ中も表示更新が破綻しないようにする

仕様案:

1. 範囲は `0〜255`
2. 表示は `0〜100%` 併記でもよい
3. `0` でもレイヤーは残す
4. 不透明度変更は即時プレビューされる
5. 将来的な Undo / Redo のため、ドラッグ開始から終了までを1操作として扱える形にする

### 4.3 レイヤーロック

現状:

1. ロック状態を保持するフィールドがない
2. 描画、塗りつぶし、反転、回転などがアクティブレイヤーに直接作用する

今回の到達点:

1. ロックされたレイヤーには編集操作が入らない
2. UI でロック状態が識別できる
3. tileset モードでも同様に動作する

追加データ案:

```javascript
{
  pixelData: PixelData,
  name: string,
  visible: boolean,
  opacity: number,
  locked: boolean,
}
```

ロック時に禁止する操作:

1. ペンシル
2. 消しゴム
3. 塗りつぶし
4. 選択切り取りの元画像変更
5. 反転、回転
6. 結合の結合先としての破壊更新

ロック時に許可する操作:

1. レイヤー選択
2. 可視/不可視切り替え
3. 名前変更
4. 不透明度変更
5. ロック解除

### 4.4 レイヤー複製

目的:

1. 変形前バックアップを即座に作れるようにする
2. 影、差分、当たり判定用の派生レイヤーを短手数で作れるようにする

仕様案:

1. アクティブレイヤーをディープコピーする
2. 複製後はコピー側をアクティブにする
3. 名前は `元名 コピー` または `元名 copy` のように自動付与する
4. 可視/不透明度/ロック状態も複製する

候補 API:

```javascript
duplicateLayer(index)
```

### 4.5 レイヤー結合

目的:

1. 作業済みレイヤーを整理して枚数を減らす
2. タイル制作終盤の軽量化と視認性向上につなげる

基本仕様:

1. まずは「下のレイヤーへ結合」のみ対応する
2. 対象はアクティブレイヤーとその1つ下のレイヤー
3. アクティブレイヤーが最背面なら結合不可
4. 結合後は1枚減り、結合先レイヤーをアクティブにする

結合ルール:

1. 合成は `LayerData.composite()` と同じアルファ規則に揃える
2. 上レイヤーの `visible=false` なら結合結果に反映しない
3. 上下いずれかが `locked=true` の場合は結合不可とする
4. 結合後の名前は原則として下レイヤー名を維持する
5. 結合後の `opacity` は 255 に正規化する案を基本とする

理由:

1. 結合後レイヤーは「見た目を焼き込んだ結果」なので、再合成前提の opacity を残さない方が挙動が分かりやすい
2. 実装も Undo 用スナップショットと整合しやすい

候補 API:

```javascript
mergeLayerDown(index)
```

## 5. `LayerData` 拡張計画

### 5.1 レイヤーオブジェクト構造の拡張

現状:

```javascript
{ pixelData, name, visible, opacity }
```

拡張後:

```javascript
{ pixelData, name, visible, opacity, locked }
```

影響箇所:

1. `LayerData.init()`
2. `LayerData.addLayer()`
3. `TilesetData` の clone / paste / copy 系
4. `PixelDataConverter` の JSON/QTS 入出力
5. 将来の履歴スナップショット

### 5.2 追加メソッド候補

```javascript
renameLayer(index, newName)
setLocked(index, locked)
toggleLocked(index)
duplicateLayer(index)
mergeLayerDown(index)
canEditLayer(index)
```

### 5.3 補助メソッド候補

```javascript
cloneLayerEntry(index)
blendPixelData(dstPixelData, srcPixelData, srcOpacity)
```

`mergeLayerDown()` では、既存 `composite()` のアルファ合成ロジックを流用または共通化し、
合成規則の二重実装を避ける。

## 6. UI 拡張計画

### 6.1 `LayerPanel` の役割拡張

現状の `LayerPanel` は一覧 + 4ボタン構成である。
これを壊さずに、次の情報を追加する。

追加候補:

1. ロックアイコン列
2. アクティブレイヤー不透明度スライダー
3. 複製ボタン
4. 結合ボタン

UI 方針:

1. 行ごとの情報量を増やしすぎない
2. まずは下部操作領域を少し拡張して対応する
3. 不透明度は一覧行内ではなく下部詳細欄に置く

### 6.2 最小 UI 案

一覧行:

1. 目アイコン
2. ロックアイコン
3. レイヤー名

下部操作欄:

1. `+` 追加
2. `−` 削除
3. `↑` 前面へ
4. `↓` 背面へ
5. `D` 複製
6. `M` 下へ結合

下部詳細欄:

1. `Opacity: 100%`
2. 横スライダー

実装状況:

1. ロック列、複製ボタン、結合ボタン、不透明度詳細欄は実装済み
2. LayerPanel 経由の操作は Undo / Redo 確認済み

### 6.3 代替 UI 案

もし `LayerPanel` 内への詰め込みが厳しい場合は、
レイヤー詳細用の小ダイアログまたはミニウィンドウを別途出す。

ただし初回実装では、別ウィンドウ追加より `LayerPanel` 内完結を優先する。

## 7. `EditorScene` 側の対応

`LayerData` だけではロックは効かない。
編集操作の入口側でもガードが必要。

主な対象:

1. `EditorScene._applyTool()`
2. `EditorScene._floodFill()`
3. 反転、回転メニュー処理
4. 選択切り取り、貼り付け確定処理
5. 将来の Undo / Redo コマンド実行前チェック

基本ルール:

1. アクティブレイヤーが locked の場合、破壊更新を行わない
2. 必要ならステータス表示や簡易メッセージで理由を返す
3. ロック中でもスポイトや表示系操作は許可する

## 8. ファイル形式への影響

レイヤー情報は既に JSON v2 / QTS へ一部保存されている。
`locked` を追加するなら入出力更新が必要になる。

### 8.1 JSON

各レイヤーの保存項目に `locked` を追加する。

例:

```json
{
  "name": "影",
  "visible": true,
  "opacity": 180,
  "locked": false,
  "data": "..."
}
```

後方互換:

1. `locked` が無い既存データは `false` 扱い

### 8.2 QTS

既存バイナリ仕様にレイヤーメタがあるため、
将来的には `visible` と `opacity` に加えて `locked` も入れたい。

ただし注意点:

1. QTS の互換性を壊す変更になる可能性がある
2. 先に JSON 対応を行い、QTS はバージョン更新時に追随でもよい

初回実装方針:

1. まずはランタイムと JSON を対応
2. QTS は別フェーズでバージョン管理込みで対応

## 9. Undo / Redo との接続方針

この計画は単独でも実装できるが、
最終的には `UNDO_REDO_PLAN.md` と接続する前提で設計する。

コマンド化対象:

1. レイヤー名変更
2. 不透明度変更
3. ロック切り替え
4. レイヤー追加
5. レイヤー削除
6. レイヤー移動
7. レイヤー複製
8. レイヤー結合

特に注意する点:

1. 不透明度スライダーは連続変化を1履歴にまとめる
2. 結合は破壊的なので、対象2レイヤーの完全スナップショットが必要
3. 複製は新規レイヤー挿入と activeIndex 変化をまとめて戻せる必要がある

## 11. 実装順の推奨

実装効率と破壊リスクの低さを考えると、順番は次がよい。

1. `LayerData.renameLayer()` を追加して既存の直接代入を置き換える
2. `locked` を追加し、clone / import / export の既定値を揃える
3. `duplicateLayer()` を追加する
4. `LayerPanel` に複製ボタンとロック表示を追加する
5. `EditorScene` にロックガードを入れる
6. `LayerPanel` に不透明度スライダーを追加する
7. `mergeLayerDown()` を追加する
8. 最後に JSON 永続化と履歴対応へつなぐ

この順序なら、難しい結合処理を最後に回しつつ、
ユーザー価値の高い機能を先に出せる。

## 12. 主要な注意点

### 12.1 tileset モードでの影響範囲

タイルセットでは各チップが独立した `LayerData` を持つ。
そのためレイヤー複製や結合は「現在選択中チップだけ」に作用する。

ここを曖昧にすると、
「タイルセット全体のレイヤー構成を変える機能」と誤解されやすい。

初回実装では次を明記する。

1. 作用対象は常に現在選択中チップ
2. 全チップ一括のレイヤー構造変更は別機能

### 12.2 レイヤー結合の仕様固定

結合処理は後から仕様がぶれやすい。
先に次を固定してから実装する。

1. 結合方向は下固定か
2. 名前はどちらを残すか
3. opacity を焼き込んで 255 にするか
4. locked / visible をどう扱うか

この計画では以下を推奨する。

1. 結合方向は下固定
2. 名前は下レイヤー維持
3. 見た目を焼き込んで opacity は 255
4. どちらか locked なら結合不可

### 12.3 ロック時の選択ツールとの整合

選択範囲の確定やカット処理は実質的にレイヤー編集である。
そのため、ロック状態のときは次を禁止対象として統一する。

1. カット
2. 貼り付け確定
3. 浮動選択の元画像削除
4. 選択範囲への変形適用

## 13. 動作確認項目

### 基本

1. free モードでレイヤー名変更が反映される
2. tileset モードで選択チップのレイヤー名変更が反映される
3. 不透明度変更で composite 表示が即時変化する
4. ロック中に描画、塗りつぶし、反転、回転が効かない
5. レイヤー複製で内容、名前、opacity、visible、locked が複製される
6. レイヤー結合で見た目が期待通り維持される

### 境界ケース

1. 1枚しかないとき削除不可
2. 最背面レイヤーでは結合不可
3. `opacity=0` のレイヤー複製が壊れない
4. `visible=false` レイヤー結合時の仕様通りに動く
5. locked レイヤーをアクティブにしてもスポイトは使える
6. JSON 読込で `locked` 欠落時も正常動作する
