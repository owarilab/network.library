# プロジェクト管理・シーン遷移基盤 計画書

最終更新: 2026-04-26

## 目的

現在の `qs_tool_server` は、マップチップ作成可能なドット絵エディタシーンを中心に構築されている。
次フェーズでは、マップエディタや将来の派生ツールを追加できるよう、
アプリ全体の入口となるタイトルシーンと、プロジェクト単位で各機能へ入るプロジェクトトップシーンを導入する。

同時に、「どのシーンで何を編集中か」を横断的に保持するため、
全シーンを束ねる `Project` 概念を追加し、新規作成・ロード・シーン間データ引き継ぎの基盤を整備する。

---

## 背景

- 現状の主シーンはドット絵エディタ中心で、起動直後にそのまま編集へ入る構成になっている
- 今後はマップエディタ、素材管理、設定画面など複数シーンへ拡張したい
- 現在の `AppData` は単一シーン運用寄りで、プロジェクト単位の永続データ管理責務が薄い
- 派生シーンが増える前に、入口と遷移ルールを定めておかないと依存関係が散らばりやすい

---

## このフェーズで達成すること

1. 起動時に入る `TitleScene` を追加する
2. プロジェクト作成後またはロード後に入る `ProjectTopScene` を追加する
3. `Project` をアプリの管理単位として定義する
4. ドット絵エディタシーンを `Project` 配下の1機能として再配置する
5. 今後のマップエディタなどへ同じ方式で遷移できる土台を作る
6. シーン間の共有データを `Project` / `AppData` の責務に分離する

---

## スコープ

### 対象

- タイトルシーン追加
- プロジェクトトップシーン追加
- プロジェクト作成フロー追加
- プロジェクトロードフロー追加
- シーン遷移時の共有データ受け渡し基盤追加
- 既存ドット絵エディタシーンのプロジェクト配下化

### 今回は対象外

- マップエディタ本体の詳細実装
- アセットブラウザ本体の詳細実装
- サーバー保存、クラウド同期、チーム共有
- プロジェクトファイル形式の完全確定
- 派生シーンごとの個別編集仕様

---

## 目指す画面遷移

```text
起動
  ↓
TitleScene
  ├─ 新規プロジェクト
  │    ↓
  │  Project 作成
  │    ↓
  │  ProjectTopScene
  │    ├─ ドット絵エディタ
  │    │    ↓
  │    │  PixelEditorScene
  │    │    ↓
  │    │  ProjectTopScene へ戻る
  │    ├─ マップエディタ
  │    │    ↓
  │    │  MapEditorScene
  │    └─ その他派生シーン
  │
  └─ プロジェクトをロード
       ↓
     Project 復元
       ↓
     ProjectTopScene
```

ポイントは、各編集シーンへ直接飛ぶのではなく、必ず `ProjectTopScene` を経由させること。
これにより機能追加時の入口が揃い、各シーンの責務も整理しやすくなる。

## 新しく導入する概念

## 1. Project

`Project` は、このツールにおける最上位の作業単位とする。

最低限、以下を保持する。

- プロジェクト名
- 保存先または識別子
- 作成日時 / 更新日時
- 利用中の素材群
- ドット絵データ、タイルセット、将来のマップデータ
- 各機能シーンが参照する共通設定

初期フェーズでは、完全な永続化よりも「シーンをまたいで一貫した状態を保持できること」を優先する。

### 想定データ例

```js
{
  id: "project-uuid-or-temp-id",
  name: "New Project",
  version: 1,
  createdAt: 1714090000000,
  updatedAt: 1714090000000,
  assets: {
    pixelSheets: [],
    tilesets: [],
    maps: []
  },
  settings: {
    lastOpenedScene: "project_top"
  },
  runtime: {
    activeAssetId: null,
    activeMapId: null
  }
}
```

`runtime` は保存対象と切り分ける前提で扱い、
UI 状態や一時選択情報を混ぜ込みすぎないようにする。

## 2. Scene Context

シーン遷移時に必要な情報を `SceneContext` 的な引数で受け渡せるようにする。

最低限の責務:

- `appData`
- 現在の `project`
- 遷移元シーン識別子
- 遷移先で初期選択したい対象ID

これにより、各シーンがグローバル変数へ直接依存せず初期化できる。

## 3. Project Session

`Project` そのものは永続対象、
`Project Session` は編集中の一時状態という分離を意識する。

例えば以下をセッション側へ寄せる。

- 現在開いている素材
- 最後に選択していたツール
- 各ウィンドウ位置
- 一時未保存フラグ

この分離を先に意識しておくと、後からオートセーブやセッション復元を入れやすい。

## シーン責務

## TitleScene

役割:

- アプリ起動直後の入口
- 新規プロジェクト作成
- 既存プロジェクトのロード
- 最近使ったプロジェクト一覧の入口（将来拡張）

最低限の UI:

- タイトル表示
- `New Project`
- `Load Project`
- 必要なら `Recent Projects` プレースホルダ

実装方針:

- まずはシンプルな中央メニュー構成でよい
- 新規作成とロードはダイアログまたは簡易フォームで開始する
- 作成/ロード成功後に `ProjectTopScene` へ遷移する

## ProjectTopScene

役割:

- 現在開いているプロジェクトのホーム画面
- 利用可能な各ツールシーンへのハブ
- プロジェクト概要表示
- 新規素材作成や既存素材選択の入口

最低限の UI:

- プロジェクト名表示
- プロジェクト情報概要
- `Dot Editor`
- `Map Editor`（未実装なら準備中表示でもよい）
- `Back to Title`

実装方針:

- ここを全派生シーンの共通親ハブにする
- 将来的に最近編集した素材一覧やサムネイル一覧を追加できる構造にする

## PixelEditorScene

役割:

- 既存 `EditorScene` をプロジェクト配下の1機能として扱う
- 編集対象アセットを `Project` から取得する
- 編集結果を `Project` 側へ反映する

移行方針:

- 初期段階では `EditorScene` を大きく崩さずラップして移行する
- `AppData` 直置き状態を徐々に `project + active document` 参照へ寄せる

## データ引き継ぎ基盤の設計方針

## 原則

1. シーンは自分で永続データを所有しない
2. 永続データは `Project` 側へ集約する
3. シーン固有の一時状態だけを scene instance が持つ
4. 遷移時は `SceneManager` にコンテキスト付きで渡す

## 推奨責務分担

### AppData

- アプリ全体で共通な管理オブジェクト
- `sceneManager`、入力、描画管理、グローバル設定
- 現在開いている `projectSession` への参照

### Project

- 保存対象のルートデータ
- 各派生シーンが扱う編集データの実体

### Scene

- 表示、入力、編集操作
- `Project` への読み書き窓口は持つが、所有はしない

---

## 必要になりそうな実装要素

### データクラス

- `js/project/project_data.js`
- `js/project/project_factory.js`
- `js/project/project_serializer.js`
- `js/project/project_session.js`

### シーン

- `js/scene/title_scene.js`
- `js/scene/project_top_scene.js`
- `js/scene/editor_scene.js` のプロジェクト対応改修

### ダイアログ

- `js/ui/dialog/new_project_dialog.js`
- `js/ui/dialog/load_project_dialog.js` または file input ベースの導線

### SceneManager 改修

最低限ほしい API:

```js
sceneManager.changeScene(scene, context)
scene.onEnter(context)
scene.onLeave()
```

必要なら `context` を scene instance 内へ保持する。

## 進め方

## Phase 1: プロジェクト概念の最小導入

目的:

- `Project` の最小データ構造を作る
- `AppData` から参照できるようにする

作業:

1. `ProjectData` の雛形実装
2. 新規作成用 factory 実装
3. `AppData.currentProject` 追加
4. `ProjectSession` の最小実装

完了条件:

- メモリ上で空のプロジェクトを生成し保持できる

## Phase 2: TitleScene 追加

目的:

- 起動直後の入口を EditorScene から TitleScene へ変更する

作業:

1. `TitleScene` の追加
2. 新規プロジェクトボタン実装
3. ロード導線の仮実装
4. 起動シーン差し替え

完了条件:

- 起動後に TitleScene が表示される
- 新規作成で `ProjectTopScene` へ遷移できる

## Phase 3: ProjectTopScene 追加

目的:

- プロジェクト単位のホーム画面を作る

作業:

1. プロジェクト名、基本情報表示
2. ドット絵エディタへの遷移導線
3. マップエディタ用プレースホルダ導線
4. タイトルへ戻る導線

完了条件:

- 新規/ロード後に ProjectTopScene が表示される
- 既存 EditorScene に入って戻れる

## Phase 4: EditorScene のプロジェクト対応

目的:

- ドット絵エディタを project 配下の編集シーンへ寄せる

作業:

1. 編集対象を `Project` から開く導線に変更
2. 保存先を `Project` 内データへ切り替え
3. 戻る時に `ProjectTopScene` へ復帰

完了条件:

- 既存編集機能を維持したまま `Project` 経由で扱える

## Phase 5: Project の保存/ロード基盤

目的:

- 新規作成だけでなくロードも成立させる

作業:

1. JSON ベースの暫定プロジェクト形式を決める
2. serialize / deserialize 実装
3. ファイル選択からロード
4. 保存導線の基礎実装

完了条件:

- 作成したプロジェクトをロードして再度 ProjectTopScene へ入れる

## タスク分解

### 先に着手すべきもの

1. `AppData` に `currentProject` / `projectSession` を追加
2. 起動シーンを `TitleScene` に変更
3. `ProjectTopScene` を追加
4. `EditorScene` への遷移口を `ProjectTopScene` 経由へ変更

### その次

1. 新規プロジェクトダイアログ
2. 暫定 JSON 保存/ロード
3. 最近開いたプロジェクト情報
4. マップエディタ遷移プレースホルダ

---

## リスクと注意点

### 1. `AppData` の責務肥大化

`Project` を追加する際、全部を `AppData` に積むと再び単一巨大状態になる。
`AppData` は参照ハブに留め、編集実体は `Project` 側に寄せる必要がある。

### 2. `EditorScene` の既存依存

現状の `EditorScene` は単独アプリ前提の箇所が多い可能性がある。
一気に全面改修せず、最初は「プロジェクト内の現在アセットを編集する」形で薄く接続するのが安全。

### 3. 保存形式の早期固定

マップや複数アセットの仕様が未確定の段階で完全版フォーマットを固めると手戻りが出る。
まずは暫定 JSON で十分。

### 4. シーン遷移ごとの UI 状態喪失

ウィンドウ位置や現在ツールを毎回失うと使い勝手が悪い。
ただし永続化対象と一時状態は混ぜず、`ProjectSession` 側で吸収する。

---

## この計画での到達点

このフェーズが終わると、`qs_tool_server` は
「単一のドット絵エディタ」から
「プロジェクトを起点に複数ツールへ入る制作ツール」へ土台を移せる。

特に重要なのは次の3点。

1. 起動入口を統一する
2. プロジェクトを状態の基準点にする
3. 派生シーン追加時の遷移ルールを固定する

これにより、次のマップエディタ実装は個別機能追加ではなく、
既存の遷移基盤へぶら下げる形で素直に拡張できるようになる。
